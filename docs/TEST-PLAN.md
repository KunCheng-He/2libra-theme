# 2libra-theme 测试计划（v1 · 企业微信主题）

> 依据 `PLAN.md`（M1 引擎骨架 / M2 数据适配层 / M3 企微主题渲染）与实际实现（`src/`）编制。
> 执行方式：Playwright 以 CDP 连接用户 Brave（dist 已加载），对 2libra.com 真实站点进行端到端验证。
> 状态：**待审查**，审查通过后执行。

## 0. 环境与前置条件

| 项 | 内容 |
|---|---|
| 浏览器 | 用户 Brave（CDP 远程调试，playwright-cli attach，禁止下载新浏览器） |
| 被测扩展 | `dist/` 目录，开发者模式加载 |
| 视觉基准 | `~/Downloads/企业微信页面样例.png`（企微群聊视图截图） |
| 登录态 | Brave 内 2libra.com 测试账号登录态（搜索 / 回复 / 发帖 / 未读数依赖登录） |
| ⚠️ 写操作风险 | 回复、发帖为**真实写操作**，会在 2libra.com 产生真实数据。测试内容统一加 `[theme-test]` 前缀标记，测试后由用户决定是否删除 |
| ⚠️ 扩展热更新 | 改 `content.js` 后刷新页面即生效；改 `manifest.json` / `background.js` 需在 `chrome://extensions` 重新加载扩展 |

### 通用检查项（每个用例隐含）

- [ ] 扩展自身 console 无未捕获报错（`playwright-cli console`）
- [ ] 伪装 UI 始终渲染在 Shadow DOM 内，原 App 根节点保持隐藏（`display:none`）
- [ ] 操作后 URL 与真实 2libra 路由始终同步

## 执行说明

1. **执行顺序**：A → B → C → D → E →（人工/自动穿插）→ J → K → L → M → N；写链路 F/G/H 放在用户确认数据风险后执行。
2. **自动可执行**：全部场景均可通过 playwright-cli（CDP attach）自动化；仅 N 项性能数值以记录为主。
3. **需用户配合项**：
   - F2/G4 的"原版验证"需临时停用扩展（可由 popup 自动化完成，无需人工）；
   - M1/M5 未登录态需要在 Brave 中登出或提供无痕窗口方式（CDP 共享主 profile，默认有登录态）——执行前与用户确认处理方式；
   - C11（群成员栏映射差异）需用户拍板。
4. **产出物**：执行完成后输出测试报告（逐项 通过/失败/跳过 + 截图 + 差异清单 + 性能记录）。
